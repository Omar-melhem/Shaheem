# شهم | SHAHM — توثيق المشروع

نموذج أوّلي تفاعلي (Prototype) لمنصّة توصيل B2B: تربط **التجار** (مطاعم، مقاهٍ، متاجر، صيدليات…) بـ**الكباتن**، وتديرها **الإدارة** من لوحة مركزية. واجهة عربية بالكامل من اليمين لليسار.

> هذا نموذج عرض وليس نظاماً إنتاجياً: لا يوجد خادم ولا قاعدة بيانات ولا دفع حقيقي ولا رسائل SMS. كل البيانات تجريبية وتُحفظ في متصفح المستخدم.

## 1. التشغيل

المتطلبات: Node.js 20 أو أحدث.

```bash
npm install        # تثبيت الحزم (لا تحذف package-lock.json)
npm run dev        # تشغيل محلي
npm test           # فحوص قواعد العمل (179 فحصاً)
npm run build      # فحص الأنواع + بناء النسخة النهائية في dist/
npm run preview    # معاينة النسخة المبنية
```

**شرط أي تعديل:** نجاح `npm test` و `npm run build` معاً.

**النشر:** `npx -y vercel@latest deploy --prod --yes` من جذر المشروع (حساب Vercel: omar-melhem).

## 3. البنية المعمارية

الاعتماد باتجاه واحد: `domain` ← `application` ← `features`. الواجهة لا تملك قواعد التسعير أو التوزيع أو المحفظة أو انتقالات حالة الطلب.

```text
src/
  app/              التوجيه وتركيب التطبيق (App.tsx)
  domain/           قواعد صافية بلا React: الأنواع، المال، الحالات، الأهلية، المناطق، الوقت، الهاتف، العمولة
  application/      حالات الاستخدام والمتجر (store.ts)، الاستعلامات، جولات التوزيع، نسخ الأسعار، الجلسة
  infrastructure/   بيانات العرض (seed.ts) والبحث عن الأماكن
  features/         الشاشات حسب الدور: admin / merchant / captain / auth / demo / support
  shared/           مكوّنات مشتركة (ui/، الخرائط، الإشعارات) وأدوات مساعدة
tests/              فحوص قواعد العمل
docs/               وثائق (هذا الملف + عقد المحفظة والعمولة للخادم)
```

### قواعد ثابتة في الكود
- **المال** أعداد صحيحة بالفلس (`jodToFils`، `formatMoney`)، ولا أرقام عشرية للمال.
- **حالات الاستخدام** تُرجع `Result`، وتُعرض للمستخدم بإشعار عبر `reportResult()`.
- **الإشعارات** مكوّن `Toaster` واحد أعلى يمين الشاشة.
- **رقم الهاتف** 10 أرقام بالضبط (`domain/phone.ts` + `PhoneField`)، ويعيد المتجر التحقق منه.
- **الوقت** بتوقيت عمّان (`domain/time.ts`).
- **المكوّنات المشتركة** في `src/shared/components/ui/`، ملف لكل مكوّن، ولا تستورد من `features`.

## 4. الأدوار والشاشات

### 4.1 الإدارة — `/admin`

| الصفحة | المسار | ما تقدّمه |
|---|---|---|
| لوحة التحكم | `/admin` | مؤشرات التشغيل، تنبيهات، أحدث الطلبات مع إجراءات العرض والإلغاء |
| مركز التوزيع | `/admin/dispatch` | الطابور اليدوي، جولات البث، الطلبات المؤجلة، الإسناد الخاص لكابتن |
| الخريطة الحية | `/admin/map` | مواقع الكباتن فقط مع حالتهم وحداثة الموقع؛ `?captain=id` يفتحها على كابتن محدد |
| الطلبات | `/admin/orders` | بحث وفلاتر (الحالة، التاجر، الكابتن، المنطقة) وتفاصيل الطلب وسجله؛ `?merchant=` و`?captain=` تفتحها مفلترة |
| التجار | `/admin/merchants` | إضافة وتعديل وتفعيل وإيقاف، فئة النشاط، موقع الاستلام، طلبات التاجر |
| مناطق التاجر وأسعاره | `/admin/merchants/:id/zones` | تفعيل المناطق للتاجر وسعر كل منطقة |
| الكباتن | `/admin/captains` | فلاتر الحساب والتوفر والبحث، شحن المحفظة من الصف، التقييم، الموقع على الخريطة، سجل الرحلات لثلاثة أيام |
| مناطق التوصيل | `/admin/areas` | المحافظة ← المدينة ← المنطقة ← أقسام، استيراد جماعي، مسارات التوصيل |
| أسعار التجار | `/admin/pricing` | بطاقة لكل تاجر، فلترة حسب منطقة مسعّرة وعدد المناطق المسعّرة (من/إلى)، نسخ الأسعار بين التجار |
| محافظ الكباتن | `/admin/wallets` | الأرصدة والأهلية، الشحن (محاكاة)، سجل الحركات |
| بيانات الدعم | `/admin/support` | بيانات التواصل التي تُعرض للتجار والكباتن |
| الإعدادات | `/admin/settings` | إعدادات للقراءة فقط وحاسبة العمولة |

**معيار الجداول الموحّد** (`DataTable` + `IconAction`) في كل جداول الإدارة:
- عناوين واضحة للأعمدة، وخط فاصل بين كل عمودين، ولونان فقط للصفوف بالتناوب.
- الإجراءات أيقونات فقط، ولكل أيقونة تلميح عند المرور أو التركيز بلوحة المفاتيح، مع `aria-label`.
- بجانب «الإجراءات» أيقونة تنبيه تشرح أيقونات ذلك الجدول فقط.
- الإجراءات الحساسة أو المالية لها نافذة تأكيد.

**القوائم المنسدلة:** مكوّن `Select` واحد مشترك. سهم المتصفح مخفي، ويظهر سهم واحد في الطرف الأيسر على بعد 14px من الحافة.

### 4.2 التاجر — `/merchant`
- **طلب كابتن:** أولاً «طلب فوري» أو «طلب مؤجل» (تاريخ ووقت في المستقبل بتوقيت عمّان).
  - **منطقة التوصيل** إلزامية، وتُختار من مناطق التاجر المفعّلة والمسعّرة.
  - **هاتف العميل** اختياري، ويجب أن يكون 10 أرقام إن أُدخل.
  - **الموقع الدقيق على الخريطة** اختياري.
  - **لا يوجد حقل لاسم العميل، ولا لقيمة البضاعة.**
  - بعد التعبئة تظهر نافذة مراجعة، ثم يُنشأ طلب واحد.
- **الرسوم:** ثابتة لكل تاجر ومنطقة، وتُعرض للقراءة فقط وتُثبَّت على الطلب.
- **متابعة الطلبات:** الطلبات النشطة والسابقة مع حالتها.
- **مناطقي** (`/merchant/areas`): قائمة مناطق التاجر وأسعارها، للقراءة والطباعة.
- **الإعدادات** (`/merchant/settings`): بيانات الحساب للقراءة فقط. التاجر لا يعدّل ملفه أو موقعه أو أسعاره، ولا يملك إلغاء الطلبات.

### 4.3 الكابتن — `/captain` (مصمّم للجوال أولاً)
تبويبات: **الطلبات** (العروض) · **التوصيل** (الطلب الجاري) · **السجل** · **المحفظة** · **حسابي**.
- مفتاح «متاح / غير متاح» مع فحص الأهلية.
- **قبول العرض:** التحقق مرة أخرى من الأهلية، ومنع قبول نفس الطلب من كابتنين.
- **خطوات التوصيل بالترتيب بدون تخطي:** تم القبول ← في الطريق إلى التاجر ← تم الاستلام ← في الطريق إلى العميل ← تم التسليم.
- **التسليم** يؤكده الكابتن فقط، بدون رمز OTP أو صورة أو توقيع.
- **السجل:** الرحلات المكتملة لليوم وأمس وقبل أمس حسب تقويم عمّان.

## 5. قواعد العمل الأساسية

### حالات الطلب
`pending_dispatch` بانتظار التوزيع · `awaiting_captain` معروض على الكباتن · `offered_privately` معروض بشكل خاص · `accepted` تم القبول · `heading_to_pickup` في الطريق إلى التاجر · `picked_up` تم الاستلام · `on_the_way` في الطريق إلى العميل · `delivered` تم التسليم · `cancelled` ملغي · `dispatch_expired` انتهى التوزيع دون إسناد.

الانتقالات المسموحة مركزية في `domain/orderStatus.ts`، ولا تنفّذها الواجهة بنفسها.

### التوزيع (v1.2 §5)
- البث العام يكون على **جولات مدة كل منها 60 ثانية، بحد أقصى 3 جولات**. بعدها ينتقل الطلب إلى طابور الإدارة مع سبب واضح، ولا تُضاف جولة رابعة ولا يُلغى الطلب تلقائياً.
- مفتاح «البث العام» منفصل عن الإسناد الخاص. إيقاف البث لا يلغي التوصيلات الجارية ولا يمنع الإسناد اليدوي.
- **الطلبات المؤجلة** لا تدخل البث العام أبداً، حتى بعد حلول وقتها. تنسّقها الإدارة عبر واتساب (برسالة جاهزة للنسخ، بدون أتمتة وبدون بيانات العميل) ثم تسندها لكابتن بشكل خاص. إذا رفض الكابتن يعود الطلب للطابور اليدوي.
- من يستقبل كل جولة هو سياسة عرض تجريبية (قرار مفتوح O-005).

### التسعير والمناطق (v1.3 / v1.4)
- **هرم المناطق:** المحافظة ← المدينة ← المنطقة ← أقسام اختيارية (مستوى واحد). الإدارة تدير المناطق بالأسماء، **بدون رسم حدود على الخريطة**.
- **لكل منطقة أو قسم سعر مستقل** لكل تاجر، ولا يرث القسم سعر منطقته.
- **«تغطية التاجر» ليست سعراً.** المنطقة متاحة للطلب فقط إذا كانت **نشطة ومفعّلة للتاجر ومسعّرة**.
- **«تحديد جميع المناطق»** يفعّل كل المناطق النشطة في الكتالوج، لا نتائج البحث فقط. المناطق المضافة لاحقاً لا تُفعَّل تلقائياً.
- **نسخ الأسعار بين التجار:** يملأ الأسعار الناقصة فقط، والكتابة فوق الموجود تحتاج تأكيداً منفصلاً. كل نسخ يُسجَّل في سجل التدقيق.
- **سعر الطلب يُثبَّت عند إنشائه** ولا يتغيّر بعدها. الموقع الدقيق لا يغيّر السعر، والتسعير ليس بالمسافة أبداً.

### المحفظة والعمولة
- الشحن من الإدارة **محاكاة** وليس تحويلاً بنكياً. الرصيد يُحسب من سجل الحركات.
- حد الأهلية التجريبي 2.00 د.أ (قرار مفتوح O-020).
- **العمولة** نسبة من رسوم التوصيل، والنسبة المقترحة 20% (بالفلس، تقريب نصف للأعلى). **غير مفعّلة كخصم**: الخصم يحتاج خادماً يضمن خصماً واحداً لكل طلب. التفاصيل في [`docs/wallet-commission-backend-contract.md`](wallet-commission-backend-contract.md).

### الموقع و GPS
- يُتتبَّع موقع الكابتن أثناء التوصيل النشط فقط. **لا يُعرض موقع قديم أو تجريبي على أنه مباشر.**
- الطلب بدون موقع دقيق يظهر للكابتن والإدارة بعبارة «لا يوجد موقع دقيق»، ولا يُخزَّن له موقع تقديري.

### ما هو محذوف عمداً (بقرار المالك)
- **حقل جهة الاتصال للتاجر:** للتاجر هاتف النشاط فقط.
- **أي بيانات مركبة للكابتن.**
- **اسم العميل في الطلب.**
- **قيمة البضاعة في الطلب:** تبقى للقراءة فقط على الطلبات القديمة.
- **أرقام دعم أو بريد أو روابط واتساب مخترعة.**

## 8. ما لم يُطبَّق من «Master Prompt» ولماذا

ملف «SHAHM Complete Master Prompt» يطلب بناء النظام من الصفر. طُبّقت منه البنود غير المتعارضة: حذف جهة الاتصال والمركبة واسم العميل، معيار الجداول، فلاتر الكباتن والأسعار، الشحن من صف الكابتن، والقوائم المنسدلة.

لم تُطبَّق البنود التالية لأنها تخالف قرارات معتمدة سابقاً:

| البند | السبب |
|---|---|
| ألوان كحلي/زمردي | الهوية الرسمية لشهم معتمدة |
| shadcn/ui و Recharts وإعادة ترتيب المجلدات | لا مكتبات أو إعادة هيكلة بدون موافقة |
| حجز رسوم التوصيل وخصمها من المحفظة في المتصفح، وشرط الرصيد ≥ الرسوم | العمولة نسبة وتحتاج خادماً (CR v1.4 §3) |
| أرصدة تجريبية 0/1/5/10 د.أ | مرتبطة بنموذج المحفظة أعلاه |
| هاتف العميل إلزامي | CR v1.4 §4 جعله اختيارياً |
| إدخال الرسوم وتعليمات التوصيل وملاحظات الموقع في طلب التاجر | الرسوم ثابتة ومقفلة، والحقول الأخرى أُزيلت بقرار المالك |
| علامات التاجر ونقاط التسليم على الخريطة الحية | Feature Updates v1.2 جعلها للكباتن فقط |
| رسم نشاط الطلبات وبطاقة الرسوم المحصّلة | لوحة التحكم بُسّطت بطلب سابق |

أي بند من هذه يمكن تطبيقه إذا اعتمده المالك صراحة.

## 9. حدود النموذج

- **لا مزامنة بين الأجهزة:** البيانات في متصفح كل مستخدم، وتغييرات جهاز الإدارة لا تظهر على هاتف كابتن آخر. للعرض الكامل تُستخدم أدوار متعددة في نفس المتصفح (والتبويبات تتزامن).
- **لا ضمانات مالية:** الحالة على جهاز العميل لا تضمن أمان المعاملات كما في الإنتاج.
- **الأسعار والمواقع والأسماء تجريبية**، وليست أسعار سوق أو بيانات حقيقية.
- **التحويل إلى منتج حقيقي** يحتاج: خادماً وقاعدة بيانات، مصادقة حقيقية، تحديثات لحظية (realtime)، وتنفيذ المحفظة والعمولة على الخادم حسب العقد في `docs/`.
