## C. Architecture refactor (Clean Architecture)

### What changed

| Before | After |
|---|---|
| `application/store.ts` created a React zustand store and wrote to `localStorage` directly | `createApplicationStore(seed, repository)` — a **vanilla** store over an `AppRepository` **port** |
| `AppData` type lived in `infrastructure/seed.ts` (application depended on infrastructure) | `application/data.ts` |
| `application/hooks.ts` (React hooks inside the application layer) | `shared/hooks/application.ts` (presentation) |
| `application/session.ts` (sessionStorage) | `infrastructure/session.ts` |
| Cross-tab sync and demo clock inside the store | `infrastructure/browserState.ts` (`browserRepository`, `observeStorage`, `startSimulationClock`) |
| — | **Composition root:** `src/app/state.ts`, `src/app/session.ts` wire the concrete adapters |

### Dependency direction (verified by import search, not by folder names)

```
domain  ←  application (+ ports/AppRepository)  ←  infrastructure (adapters)
                         ↑                               ↑
                 features / shared (UI)  →  app/ (composition root wires both)
```

- `domain/` and `application/` import **no** React, `zustand/react`, `localStorage`, `sessionStorage`, `window`, `document`, Leaflet or `@/infrastructure`.
- Features never import `@/infrastructure` (the one exception is `placeSearch`, an existing adapter).
- **Persistence unchanged:** same key `shahm-demo-v8`, same `{ state, version: 1 }` format — existing demo data still loads.
- **Safer save:** the store persists the complete next snapshot *before* notifying subscribers; if saving fails, the action returns an error and memory is left unchanged.

### Fix found during review

The refactor script had written one Arabic string with the wrong encoding (`'????? ??? ?????????…'`). Replaced with:
«تعذّر حفظ البيانات. لم يُطبَّق أي تغيير، حاول مرة أخرى.»

### Patterns used (and why)

| Pattern | Where | Problem it solves |
|---|---|---|
| Repository (port + adapter) | `AppRepository` / `browserRepository` | Application no longer knows about `localStorage` |
| Dependency Injection | `createApplicationStore(seed, repository)` | Store testable and storage swappable (future API) |
| Composition root | `src/app/state.ts` | One place builds concrete dependencies |
| Observer | zustand subscriptions + `observeStorage` | Cross-tab sync without duplicate state |

Not introduced on purpose: factories, service locators, new event bus, extra stores.

`CLAUDE.md` gained a rule describing this boundary so future work keeps it.

## G. Scheduled date/time fields on iPhone Safari

**Report:** in Merchant → طلب كابتن → **طلب مؤجل**, «تاريخ الاستلام» and «وقت وصول الكابتن إلى المتجر» looked like two empty white boxes on iPhone.

### Root cause (presentation only)

- The fields were bare native `<input type="date">` / `<input type="time">` through the shared `Input` (40px, RTL page).
- **iOS Safari shows nothing at all in an empty date/time input** — no placeholder, no icon → a blank box.
- With WebKit's native styling, a 40px control in an RTL page can clip or misplace the chosen value.
- Form state, validation (`scheduledPickup`, future-only) and Amman-time conversion (`domain/time.ts`, already tested: Amman 10:00 = 07:00 UTC) were correct.

### Fix (`d46b9ad`)

New shared component **`src/shared/components/ui/DateTimeInput.tsx`**, used by `ScheduleFields.tsx`:

- Keeps the **native picker** (no new library).
- Empty state: Arabic hint «اختر التاريخ» / «اختر الوقت» that ignores taps (never blocks the input).
- Calendar / clock icon at the inline end; in Chromium the invisible picker button covers the whole field, so any tap opens it.
- 48px tall, 16px text (no iOS focus zoom), value LTR and right-aligned like the page text.
- `.shahm-datetime` rules in `src/index.css`: plain appearance, explicit text colour (`-webkit-text-fill-color`), `color-scheme: light`, WebKit value alignment; native text hidden only while empty and unfocused.
- Both inputs linked (`aria-describedby`) to the «بتوقيت عمّان…» note or the error.
- Values stay `YYYY-MM-DD` and `HH:mm`; validation, review dialog and `createOrder` unchanged.
- `CLAUDE.md`: date/time fields must use `DateTimeInput`.

### Browser verification (headless Chrome, 23/23 passed)

- Immediate request → no date/time inputs; scheduled → both present with labels.
- Empty fields show the Arabic hints; height 48px, font 16px.
- Past date/time → «اختر وقتاً في المستقبل» at the fields, no review dialog.
- Valid values are machine-readable and drawn in a visible colour (`rgb(36,36,36)`); the error clears on change.
- Resized **without reloading**: 375 → 390 → 430 → 600 → 768 → 1024 → 1440 → 1920 → 360 → 320 → 844×390 (landscape) → 1280 → 375. Values kept, visible, inside the card, no page overflow at every step.
- Review dialog shows the chosen time; switching back to «طلب فوري» removes the fields with no empty gap.

## I. Vercel: why the site does not open

**The deployment is healthy** (status *Ready*, aliased to `shahm-prototype.vercel.app`). The network blocks the `vercel.app` name:

| Test from this machine | Result |
|---|---|
| `vercel.com`, `nextjs.org`, `github.com` | Open (200) |
| Vercel's server that hosts SHAHM, addressed as `vercel.com` | Opens (200) |
| The same server addressed as `shahm-prototype.vercel.app` | Connection reset |
| Another Vercel server, SHAHM name | Connection reset |
| An unrelated `*.vercel.app` site | Connection reset |

Conclusion: blocking by domain name (TLS/SNI) on the network or ISP; it started before this session's deploys (the first check of the session already failed). The last successful check from this machine was on 10 November.

**Options:**
1. Open the link on mobile data or with a VPN (quick confirmation).
2. Connect a custom domain to the same Vercel project (permanent; needs a domain purchase).
3. Publish a copy on another host (Netlify / Cloudflare Pages / GitHub Pages) — needs approval.
