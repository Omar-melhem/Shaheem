# SHAHM Flutter — Architectural Decisions Registry

The single decision register for the Flutter app and its SHAHM server
interfaces. Other documents reference decisions by ID (`D-A..`, `D-P..`,
`D-R..`). **Owner approvals made after the 2026-11-12 document snapshot,
through 2026-11-14, supersede conflicting earlier wording. The 2026-11-20
client revision (§1.2, D-A69–D-A79) supersedes conflicting earlier wording,
including §1.1. The 2026-11-24 Home and order-details revision (§1.5, D-A82/D-A83) supersedes the specific conflicting Home/customer-data clauses; the client implementation landed 2026-11-24.** A historical
implementation decision does not prove that a new approved target is coded.

**Statuses:**
- **Approved:** stated by the project owner, in `CLAUDE.md` or a requirement
  document.
- **Pending:** not decided. Don't act on it without asking.
- **Rejected:** decided against (sometimes "for now").

**Rules:**
- Never move an item to Approved without the owner's explicit confirmation.
- Implementation choices Claude made on its own are listed separately in §4.
  They are **historical code snapshots, not approvals of current target behavior**.
- A decision row is not proof of implemented code. For actual
  implementation status see `PROJECT_STATUS.md`.
- Superseded rows keep their original text after a bold **Superseded**
  prefix, for traceability only; they are not live rules.
